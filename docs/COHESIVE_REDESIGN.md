# 냥토피아 통합 리디자인 기준

## 문제 정의

현재 버전은 개별 기능은 작동하지만 플레이 단계, 지도 피드백, UI 정보 계층, 시각 언어가 서로 다른 제품처럼 분리되어 있다. 이번 작업의 목표는 요소를 더 추가하는 것이 아니라 플레이어의 한 행동이 시스템 변화와 화면 피드백으로 자연스럽게 이어지도록 괴리를 제거하는 것이다.

## 2026-08-14 기준선

실제 브라우저 dogfood에서 확인한 값:

- 시작부터 자원 9개와 건설 도구 12개가 동시에 노출된다.
- 데스크톱 지도는 화면 상단에서 295px 아래에 시작한다.
- 1440×900에서 Canvas 면적은 viewport의 약 47.6%다.
- 390×844 모바일 첫 화면에서는 건설 도구 12개 중 보이는 도구가 0개다.
- 모바일 전체 페이지 높이는 1719px이며 지도와 건설 도구가 분리된다.
- 다음 행동을 설명하는 정보는 `0/4 · 자립 생산도시 완성`뿐이다.
- `GAME_BRIEF.md`는 도시 등급과 건물 해금을 약속하지만 현재 구현은 모든 건물을 처음부터 노출한다.

## 통합 설계 원칙

1. **지도 우선**: 첫 화면의 주인공은 통계 카드가 아니라 고양이 도시다.
2. **한 번에 한 단계**: 현재 단계에 필요한 자원, 건물, 병목만 전면에 노출한다.
3. **행동-결과 직결**: 건설 직후 지도, 임무, 자원, 인스펙터가 같은 원인을 설명한다.
4. **세계 안의 피드백**: 오프라인·공급 부족·해금은 패널뿐 아니라 시설 위 표식으로도 보인다.
5. **점진적 복잡도**: 기반 시설 → 물과 농업 → 가공 → 정주 순으로 도구와 정보가 열린다.
6. **한 시각 언어**: 지도와 UI 모두 황혼의 고양이 개척 공업도시라는 동일한 재료·색·형태를 사용한다.
7. **모바일은 축소 데스크톱이 아님**: 지도 우선, 하단 건설 dock, 선택 시 bottom sheet 구조를 사용한다.

## 목표 플레이 루프

### 1단계 — 기반 전력

- 스타터 발전소에서 취수장까지 전선을 연결한다.
- 전력 공급 여부가 시설 위 상태 표식과 임무 체크리스트에 동시에 나타난다.
- 사용 가능한 건설: 도로, 전선, 수도관, 발전소, 취수장, 정수장.

### 2단계 — 깨끗한 물

- 취수장 → 원수관 → 정수장 → 정수관을 완성한다.
- 정수 생산이 시작되면 농업 건물이 열린다.
- 사용 가능한 건설 추가: 캣닢 밭, 혼합 농장.

### 3단계 — 먹이와 재료

- 도로·정수·노동을 연결해 캣닢과 목재를 생산한다.
- 원료가 실제로 생산되면 가공·주거·행정 건물이 열린다.
- 서쪽 바깥 도시 도로에 숙소를 연결해 이주와 가용 노동력을 늘린다.
- 고양이 회관으로 최대 고양이 수를 열고 전력·물·노동·코인 조건을 맞춰 레벨 3까지 업그레이드한다.
- 사용 가능한 건설 추가: 사료 공장, 가구 공방, 숙소, 고양이 회관.

### 4단계 — 고양이 정주

- 사료·가구·숙소를 운영해 인구와 행복도를 올린다.
- 마지막 생활 건물인 캣타워 광장이 열린다.
- 자립 조건 달성 시 도시가 완성 상태로 전환된다.

## 정보 구조

### 데스크톱

- 상단 얇은 command bar: 도시명, 현재 단계, 일시정지/속도, 핵심 자원.
- 중앙 대부분: 지도.
- 좌측 지도 overlay: 현재 임무와 2–4개 체크리스트.
- 하단 dock: 단계별 건설 카테고리와 해금된 도구만 표시.
- 우측 context drawer: 선택한 시설의 상태, 필요 연결, 입출력, 철거.

### 모바일

- 상단 compact status bar.
- 첫 화면 대부분을 지도에 할당.
- 하단 sticky build dock에서 카테고리와 도구 선택.
- 시설 선택 시 인스펙터는 bottom sheet로 열림.
- 상세 자원은 접을 수 있는 economy drawer로 이동.

## 시각 언어

- 배경: 짙은 청록 야간 작업장.
- 표면: 먹색 금속, 따뜻한 목재·황동, 크림색 라벨.
- 지도: 황혼 녹지, 청록 물, 흙길, 주황 작업등.
- 상태색: 전력 청록, 물 청색, 경고 호박색, 차단 적갈색.
- 전선과 수도관은 타일·시설을 관통하는 endpoint-to-endpoint 직선 segment다. 같은 종류의 선분은 shared endpoint와 중간 grid cell 교차·중첩에서 junction으로 연결되며, 전선과 수도관 layer끼리는 서로 연결되지 않는다.
- 관로는 평상시 지형을 가리지 않고 발전소·정수장 선택 시 연결된 동일 종류 망만 glow overlay로 드러나며, 설치 중에는 밝은 직선 glow preview를 표시한다.
- 선형 시설 가격은 드래그한 기하 거리와 단가의 곱을 계산한 뒤 정수 코인으로 버린다.
- 큰 둥근 SaaS 카드와 네온 테두리를 줄이고, 얇은 금속 프레임과 명확한 계층을 사용한다.
- Grok 고양이 기술자 마스코트를 임무 안내자로 사용해 기존 아트와 실제 UI를 연결한다.

## 구현 범위

- `src/simulation.ts`: 단계/해금/임무, 직선 utility graph, 외부도로, 인구·수용력·노동, 회관 업그레이드와 마이그레이션.
- `src/simulation.test.ts`: 단계 진행, 해금 유지, 저장 마이그레이션 시나리오.
- `src/main.tsx`: map-first shell, 임무, 카테고리 dock, context inspector, in-world status.
- `src/styles.css`: 공통 토큰, 데스크톱 workspace, 모바일 dock/sheet.
- `src/terrain.ts`: 필요한 경우 상태 표식과 지도 대비를 위한 최소 조정만 수행.
- `README.md`, `docs/GAME_BRIEF.md`, `docs/DEVELOPMENT_PROCESS.md`: 실제 구현과 일치하도록 갱신.

## 실패 사전 분석과 게이트

### 위험 1 — UI만 바뀌고 게임은 여전히 막막함

게이트: 신규 저장에서 단계별 다음 행동이 항상 2–4개의 구체적 체크리스트로 표시되어야 한다.

### 위험 2 — 해금이 자원 소비 때문에 되돌아감

게이트: 도시 단계는 단조 증가하며 저장·불러오기 후 유지되어야 한다.

### 위험 3 — 모바일 dock이 지도를 가림

게이트: 390×844에서 지도, 현재 임무, 최소 하나의 건설 카테고리가 첫 화면에서 조작 가능하고 수평 overflow가 0이어야 한다.

### 위험 4 — 시스템 설명과 실제 판정이 다름

게이트: 임무 체크는 simulation의 동일한 연결·생산 판정을 사용하고 별도 UI 추정 로직을 만들지 않는다. 전선·수도관은 endpoint로도 서로를 연결하지 않는다.

### 위험 5 — 전체 리디자인 중 기존 조작이 회귀함

게이트: 배치, 연속 드래그, 철거, 팬, 일반 휠 스크롤, Ctrl+휠 확대, 저장 마이그레이션을 실제 브라우저와 자동 테스트에서 검증한다.

## 완료 조건

- 신규 플레이어가 첫 화면에서 다음 행동을 설명할 수 있다.
- 모든 화면 요소가 현재 플레이 단계 또는 선택한 시설에 직접 연결된다.
- 시작부터 12개 도구와 9개 자원을 동일 중요도로 노출하지 않는다.
- brief의 단계/해금 약속이 실제 시뮬레이션과 일치한다.
- 데스크톱과 390px 모바일 모두 지도 중심으로 작동한다.
- 전체 자동 테스트, 타입 검사, production build, browser smoke, 독립 UX/시스템 리뷰를 통과한다.
